# 0004：Delta 使用 relay 变更序号

日期：2026-11-03。状态：已实现，尚未运行迁移与客户端验证。

Messages 的 ROWID 标识原始记录。时间窗口补查可以晚插入较小 ROWID，编辑、撤回和附件更新也不会增加原消息 ROWID，因此它无法作为断线恢复的变更游标。

relay 使用 message_changes 的 SQLite AUTOINCREMENT 序号。触发器在消息、消息状态和附件写入的同一事务内更新所属消息的序号，每条消息只保存最新序号。delta 按序号分页读取当前消息快照，并返回与该快照一起读取的序号。历史分页、Messages 新增扫描和消息的 sourceRowId 字段保留原语义。

对外游标加上 2^52，以识别旧 ROWID 游标，同时保留 JSON 整数精度空间。旧游标首次升级从变更流起点重放，客户端按 GUID 合并；未初始化客户端仍从当前水位开始。代价是升级后已有客户端可能需要补同步大量记录，数据库新增一份按消息数量增长的索引。

只移除旧查询的最大 ROWID 推进不能补回已经越过的旧记录。保留所有历史变更会持续增加存储，而客户端需要的是消息最新状态，因此当前采用每消息保留最新序号。物理删除的 tombstone 不在此协议内，用户隐藏继续走独立偏好同步，撤回通过消息状态同步。
