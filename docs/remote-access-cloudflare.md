# Remote access with Cloudflare Tunnel

Remote access is optional. It connects your devices to your own public HTTPS URL; local Wi-Fi pairing works without it.

```text
client HTTPS/WSS → your Cloudflare hostname → cloudflared on Mac
                → http://127.0.0.1:3000
```

The proxy may terminate TLS. Device credentials still authenticate requests, but this is not application-level end-to-end encryption.

## Create a tunnel

Use a domain in your own Cloudflare account. These commands are for a locally managed named tunnel; replace the sample hostname.

```sh
brew install cloudflared
cloudflared tunnel login
cloudflared tunnel create micago-server
cloudflared tunnel route dns micago-server micago.example.com
```

Create `~/.cloudflared/config.yml` with the tunnel ID and credentials file generated by cloudflared:

```yaml
tunnel: <tunnel-id>
credentials-file: /Users/<you>/.cloudflared/<tunnel-id>.json
ingress:
  - hostname: micago.example.com
    service: http://127.0.0.1:3000
  - service: http_status:404
```

Use the actual local control port if you changed the default. Keep the credentials file private. Run the tunnel:

```sh
cloudflared tunnel run micago-server
```

See [Cloudflare's locally managed tunnel guide](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/create-local-tunnel/) for account setup and current CLI details.

## Configure micaGO

In Companion → Connections, enter only the public origin, such as `https://micago.example.com`, save it and validate reachability. Do not append `/api` or `/ws`.

Generate a new pairing invitation for a new device. Existing clients refresh advertised candidates through the server when reachable. If every saved address becomes unreachable, an updated configuration or re-pairing may be needed; Firestore does not currently provide a complete automatic rediscovery flow in the clients.

Test away from your home Wi-Fi. Check both authenticated REST access and WSS; a successful public health request alone does not prove that either works.

## Who runs cloudflared

You can run it separately or configure Companion's existing tunnel controls. Companion only supervises a process it starts; it must not take over or stop an external tunnel. Do not accidentally run both paths for the same test.

Mac sleep, stopped Messages, network loss and proxy rules can still affect service. FCM is a separate optional notification path and does not keep the chat API reachable by itself.
